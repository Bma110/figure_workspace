# Figure 工作台（科研稿件图管理）— 设计文档

- 日期：2026-09-08
- 状态：已与用户逐段确认后定稿
- 用途：单人本地科研用；以论文 Figure 为主体管理原始数据、图文件与溯源，标记重要/有用项，支撑 Nature 系投稿的 SourceData 与数据可得性整理

## 1. 背景与问题

用户（单个研究者，Windows 本地）当前痛点：数据散在电脑/网盘/硬盘、目录无统一规范、同名版本混乱、找不到旧结果、**说不清某张 figure/结果来自哪些数据与脚本**、怕丢与备份乱、投稿数据可得性难应付。

上一份 `思路.txt` 给出的是"项目-实验-样本-数据集-分析-图-论文"全链通用系统 + 约 20 个模块。经澄清，用户真正想要且能长期用起来的是一个**图（Figure）为主体**的窄产品，而非通用文件管理系统。本设计砍掉了思路文档中的权限/多人、ELN、全能预览等大模块。

## 2. 目标与成功标准

- 从界面新建论文工作区与 Figure，**建图即建文件夹**，原始数据通过界面上传落到对应文件夹。
- 每个图/面板可标 **状态（候选/采用/弃用/待重做）、重要度（关键/一般/辅助）、标签、备注与决策日志**。
- 从任意一张图能**溯源**到背后文件链：Fig3A ← IL6_statistics.R ← qPCR_IL6.xlsx ← 样本 ← EXP。
- 标「采用」的图可**一键导出**：SourceData 文件清单、图注草稿、数据可得性声明文本。
- 全程本地，数据不离开本机；备份简单可靠。
- 成功后每周维护 ≤ 20 分钟；不打断手头实验。

## 3. 产品范围

**做（首版 MVP）**
1. 论文工作区列表 + 新建。
2. Figure/面板树（可嵌套：Figure3 → 3A/3B/3C），磁盘与 UI 同构。
3. 看板卡片（状态色点/重要度★/标签/备注）+ 右侧详情抽屉（即用户确认过的宽松版 UI）。
4. 文件上传：拖拽/选文件 → 复制进对应文件夹并记 SHA；Ctrl+V 贴截图存为 preview.png（可选预览）。
5. 溯源：面板/图挂源文件（相对路径/sha/类型/样本字段），可反查全链。
6. 全局检索：跨论文按标签/文件名/样本/工作区名检索。
7. 扫描导入：指向已有文件夹 → 发现图片与文件 → 生成 Figure 卡片草稿，只读不动源。
8. 投稿导出：对「采用」节点生成 SourceData 清单 / 图注草稿 / 数据可得性声明。
9. 备份：一键备份 SQLite + 文件清单 +（可选）整树拷贝；定时 bat。

**不做（YAGNI，明示避免无底洞）**
- 权限/多人登录、云同步、移动端、ELN/实验记录、AI/PPT/Prism 合成稿内联预览、万能渲染、全文内容检索。

## 4. 目录/存储模型（UI=磁盘）

根目录由用户设定：`D:\ResearchData\`（启动首次运行可改）。

```
D:\ResearchData\
 ├── SA-Osteomyelitis\            ← 论文工作区（界面新建即建目录）
 │    ├── 原始数据\               ← 上传但尚未归属某张图的原始数据
 │    ├── Figure1\               ← 每个 Figure 一个文件夹（建图即建）
 │    │    ├── <源文件 1.xlsx>
 │    │    ├── <源文件 2.tif>
 │    │    └── preview.png       ← 可选：粘贴的截图预览
 │    ├── Figure2\
 │    └── Figure3\
 │         └── 3A\               ← 面板若需独立文件夹则为其子目录
 ├── Zebrafish-Sa\
 └── ...
```

规则：
- 文件系统是"真源"，SQLite 只存索引、关系、元数据，不存大文件二进制。
- 上传 = 从用户选择处**复制**（不移动），记录 SHA；删除在界面上只删记录，文件进工作台 `.trash/` 或提示确认，不做永久销毁。
- 预览截图 `preview.png` 由粘贴生成；可内联预览的类型尽力渲染缩略图，不能的显示文件卡片 + 打开。

## 5. 数据模型（SQLite 草表）

- `workspace(id, name, code, archived, created_at)` — 一篇论文一个工作区，`code` 用于目录名（如 SA-Osteomyelitis）。
- `node(id, workspace_id, parent_id NULL, kind IN('figure','panel'), label, title, status IN('candidate','adopted','rejected','redo'), importance IN('key','normal','aux'), note, preview_path NULL, created_at, updated_at)` — Figure 与面板统一为可嵌套节点（parent 成树）。
- `tag(id, name)` + `node_tag(node_id, tag_id)` — 跨论文检索用。
- `file_item(id, workspace_id, node_id NULL, rel_path, name, ext, size, sha256, sample_note, created_at)` — `node_id` 为空表示在"原始数据"区未归属。`rel_path` 相对工作台根。
- `log_entry(id, workspace_id, node_id, ts, text)` — 决策日志/备注流水（时间戳式）。

状态/重要度枚举在前端显示为中文：候选/采用/弃用/待重做；关键/一般/辅助。SQLite 内用英文枚举码，UI 映射中文。

## 6. 页面与关键交互

1. **工作区列表**：所有论文；新建/归档；进入看板。
2. **图看板**（主界面，已确认布局）：顶部工作区信息 + 过滤(状态/重要度/标签) + 扫描导入 + 新建 Figure；中栏 Figure 卡片（左色条=状态，★=重要度，tags，↑N 来源）；右侧详情抽屉（选中图）：改状态/重要度、面板缩略区、溯源区、备注/决策日志 textarea、投稿对接区。
3. **全局检索**：跨论文按标签/文件名/样本/工作区名列出结果，可跳转到对应节点。
4. **新建/扫描导入向导**：新建工作区填名称代码；扫描导入选文件夹 → 预览发现结果 → 生成草稿卡片。
5. **设置**：根目录、备份执行与查看。

上传与预览交互：看板/抽屉内拖拽或选文件；目标位置 = 当前节点文件夹，未归属则 `原始数据/`；`Ctrl+V` 粘贴剪贴板图片存为该节点 preview.png。

溯源交互：节点"溯源区"列出已挂文件（路径/sha/样本/旧版）；任意文件项点开可见工作台内相对路径并可定位；父级推导全链。

## 7. 投稿导出（采用节点）

单个"导出"动作对当前工作区内所有 `status=adopted` 节点生成：
- **SourceData 清单**：每张采用图列出其源文件（相对路径/SHA/类型），导出为文本/CSV。
- **图注草稿**：按 label+title+备注拼一段初稿。
- **数据可得性声明**：可编辑文本骨架，可并入投稿材料。
导出纯文本生成，先不做 Word/PDF 排版。

## 8. 技术栈与运行

- 后端：Python 3 + FastAPI，SQLite（stdlib `sqlite3` 即可，不引 ORM 以减依赖）。
- 前端：静态 HTML/CSS/原生 JS，由 FastAPI 托管；无构建步骤。
- 启动：Windows `启动工作台.bat` → 建 venv、装 `requirements.txt`、确保根目录、`uvicorn 127.0.0.1:8000`，浏览器打开。
- 数据位置：代码/DB 在应用目录；科研文件在 `D:\ResearchData\`。
- 无鉴权（单机单人）；局域网不绑定（仅 127.0.0.1）。

## 9. 风险与取舍（记录）

- 磁盘同构 + 上传复制：空间可能翻倍 → 上传时记录源路径可后续清理；按图归类优于全池复制，接受。
- 靠命名解析样本只是"尽力"，不承诺全自动；样本字段以界面上填写的 `sample_note` 为准。
- 截图预览降低对内联渲染的依赖（AI/Prism 合成稿不必能渲染）。
- 扫描导入只读、生成草稿需人工校正，不自动移动任何文件。
