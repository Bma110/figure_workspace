## 阶段一：设计与范围收敛（09-08）

先出了 [设计文档](superpowers/specs/2026-09-08-figure-workspace-design.md)，与用户逐段确认后定稿。

关键取舍——**砍掉通用化，做成「图为主体」的窄产品**。最初的构想是一套「项目→实验→样本→数据集→分析→图→论文」全链科研数据中台（见 `思路.txt`），约 20 个模块。经澄清，用户真正能长期用起来的是围绕 Figure 的溯源与投稿整理。于是明确列出**不做**的清单：权限/多人、云同步、移动端、ELN、万能预览、全文内容检索。

架构定调：**文件系统为真源，SQLite 只存索引与关系，不存大文件**。目录与界面同构——建 Figure 即建同名文件夹。

## 阶段四：浏览器验收与缺陷修复（09-11）

Task 11、Task 12 用真实浏览器逐项验收（11/11、12/12）。验收发现一个只有真跑界面才会暴露的缺陷：

- `61466e9` **顶栏与抽屉互抢点击**——抽屉的关闭按钮点不动。根因是顶栏 `position:sticky` + 全宽 + `z-index:25` 盖住了抽屉顶部。修法不是继续叠 z-index，而是让二者**竖向错开**（顶栏固定高度 `--topbar-h:72px`，抽屉 `top:var(--topbar-h)`）。

## 阶段五：打包 + 真实使用反馈修复（09-11）

- `1580f04` Windows 一键启动脚本 `启动工作台.bat`（首次自动建虚拟环境、装依赖）+ 使用说明。
- `128d2df` **真实使用中暴露的两个问题**（用户报：「不能预览 tif？新建的 figure 无法删除或者隐藏？」）：
  1. **TIF 不能预览**。根因：扫描导入**无条件**把预览命名为 `preview.png`，即使源文件是 `.tif`——磁盘上于是有一个「名为 `.png`、内容却是 TIFF」的文件，浏览器按 PNG 解码失败。且 Chrome/Firefox 本身就不渲染 TIFF，光改扩展名也不够。修法：装 Pillow，新增 `fw/imaging.py`，导入时把不可渲染格式转成真 PNG。
  2. **Figure 删不掉也藏不了**。删除接口存在但前端无入口，且只清库、磁盘文件夹变孤儿目录。修法：`delete_node` 连同文件夹移入 `<工作区>/.trash/`；新增节点级 `archived` 字段，支持隐藏/恢复。
- 同期补了 SQLite **显式迁移**：`CREATE TABLE IF NOT EXISTS` 不会给已存在的表补列，因此 `db._migrate` 用 `ALTER TABLE ADD COLUMN` 幂等补 `archived`，并对用户真实的 35 节点库副本验证过、数据完好。

## 决策速查

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 产品范围 | 「图为主体」窄产品 | 通用中台做不完也用不起来；砍掉权限/云同步/ELN/全文检索 |
| 真源 | 文件系统 | SQLite 只存元数据，删记录不毁文件 |
| 图片预览 | 装入时转 PNG | 浏览器不渲染 TIFF；原图另存留档，SHA 与原文件一致 |
| 删除语义 | 移入 `.trash` | 可找回，不做永久销毁 |
| 迁移 | 显式 `ALTER TABLE` | SQLite 的 `CREATE TABLE IF NOT EXISTS` 不补列 |
| 前端 | 原生 JS，无构建 | 单人本地工具，免去工具链维护 |
